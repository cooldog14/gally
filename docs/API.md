# Gally HTTP API

The contract between the bundled client and the Rust server. Everything is
same-origin; there are no external services. Base URL is
`http://127.0.0.1:8000` locally; in production it is behind the TLS reverse
proxy.

JSON is used for control responses. Upload bodies are raw bytes. Media
responses are the stored file (or its JPEG preview). The bundled client in
`app.js` is the reference consumer.

Requests that send a JSON body to `resolve`, `visibility`, `lock`, or admin
`unlock` require `Content-Type: application/json`; a missing or different
type is `415`. A bodyless request is allowed.

## Conventions

### Keys, slugs, and stored names

- `X-Gallery-Key` is the owner credential. The server trims it and accepts
  6–128 characters. The bundled UI is stricter: visible ASCII with no spaces;
  newly created keys need 12+ characters, a capital, and a symbol.
- `X-Gallery-Slug` selects the target gallery for uploads. It is optional for
  a full-body upload (absent = mint a new gallery) and required for chunked
  uploads.
- `X-Invite-Code` is required only when `GALLY_INVITE_CODE` is set and the
  request mints a new gallery. Existing galleries never need it. Wrong codes
  count toward the 10/min/IP failure bucket: the first attempts are `403`, and
  further attempts are `429` once the bucket is full. A correct code still
  works.
- Slugs are generated by the server: four lowercase words plus four hex
  characters (for example `velvet-lagoon-quiet-river-1a2b`). Galleries created
  before the 2026-10-30 slug change use `adj-noun-N` (for example
  `happy-otter-7`). Those legacy slugs and their files remain valid for URLs,
  owner keys, listings, delete, sweep, and backup. Treat slugs as opaque;
  clients should copy what the API returns.
- A stored photo name is `<slug>_<32 hex>_<sanitized filename>`. The 32-hex
  part is the upload id for resumable uploads and a random value for
  full-body uploads. The sanitized filename keeps ASCII letters, digits, `.`,
  `_`, and `-`; other characters become `_`; path components are stripped;
  the basename is capped at 100 characters.
- The server never trusts a client-supplied stored name for media access: it
  re-checks the name against a known gallery and canonicalizes the path
  inside `photos/`.

### Cookies

| Cookie | Lifetime | Path | Flags | Purpose |
|---|---|---|---|---|
| `admin` | 24 h | `/` | `HttpOnly; SameSite=Lax`, `Secure` if configured | Admin API |
| `galowner_<slug>` | 12 h | `/photos/` | `HttpOnly; SameSite=Lax`, `Secure` if configured | Owner media (`<img>`/`<video>`) |
| `galpass_<slug>` | 12 h | `/photos/` | `HttpOnly; SameSite=Lax`, `Secure` if configured | Viewer media after a password succeeds |

`galowner_*` is minted by a listing request that carries the gallery key.
`galpass_*` is minted when a viewer password succeeds on a listing or media
request. Changing the viewer password bumps the gallery token version and
invalidates every existing `galpass_*` cookie. Cookie `Path=/photos/` is why
media tags work without headers while API calls still use
`X-Gallery-Key`/`X-Gallery-Pass`.

The viewer password is sent as `X-Gallery-Pass` or carried by the
`galpass_*` cookie; media tags (`<img>`/`<video>`) rely on the cookie. The
header is percent-decoded, so non-ASCII passwords survive. Prefer the cookie
for subsequent media requests.

### Rate limits

| Bucket | Default | Scope |
|---|---|---|
| Uploads | 60/min/IP | Resolve/mint, full-body PUTs, the first chunk (`start=0`) of a resumable upload, visibility/password changes, and admin unlock |
| Resumable chunks | 600/min/IP | Every chunk of a resumable upload, including the first |
| Reads | 12,000/min/IP | Listings and every media/thumbnail request |
| Failed keys/passwords | 10/min/IP | Wrong key or viewer password, including admin login, and wrong invite codes |

`GALLY_RATE_MAX=0`, `GALLY_CHUNK_RATE_MAX=0`, and `GALLY_READ_RATE_MAX=0`
disable those buckets, but the 10/min failure lockout always applies. A
rate-limited request returns `429`; the error string depends on the endpoint
(`too many uploads`, `too many requests`, or `too many attempts`).
Upload and chunk throttles include `Retry-After`: whole seconds, rounded up
until a slot opens. Pause new uploads in the batch until then.

### Errors and status codes

Errors are JSON:

```json
{ "error": "unknown gallery" }
```

Some responses add fields: `received` on upload offset mismatches, `locked` on a lock
denial, `deleted`/`files` on deletes, `ok`/`free_bytes` on health.

| Status | Meaning |
|---|---|
| `200` | Success |
| `201` | File stored |
| `202` | Chunk stored, more expected |
| `302` | Invalid page slug redirects to `/` |
| `308` | `/gally/admin` redirects to `/gally/admin/` |
| `400` | Malformed body, header, cursor, or filename |
| `401` | Missing key where required, or a locked gallery without a password |
| `403` | Key does not own the target, missing/wrong invite, or admin required |
| `404` | Unknown, private, or not-yours resource |
| `408` | Upload idle timeout or interrupted body |
| `409` | Upload offset mismatch, or another request owns the upload id |
| `410` | Resumable upload temp is gone; restart the file |
| `413` | File/gallery/photo limit exceeded |
| `415` | JSON body sent without `Content-Type: application/json` |
| `416` | Unsatisfiable `Range` |
| `429` | Rate limit or failure lockout |
| `500` | Internal error; files are kept where the recount can repair them |
| `503` | No upload slot (`busy`), or `/healthz` not ready |
| `507` | Free-space floor reached (`storage full`) |

Private galleries answer `404` for listings and media to anyone who is not the
owner, so a slug cannot be probed. A wrong key is counted before the `404`;
repeated guesses become `429`.

### Caching, ETags, and ranges

- Listings and all authorized originals and previews, including public media
  and `206` and `304` responses: `Cache-Control: private, no-store`.
  Requests always have to pass the current gallery access checks.
- Static files: `Cache-Control: no-cache` plus an ETag; `If-None-Match`
  returns `304`.
- Full media responses carry an ETag; all media supports `Accept-Ranges: bytes`. One range is
  supported, including a suffix (`bytes=-N`, where `N` larger than the file
  means the whole file). Multiple ranges are answered with the full file.
  An unsatisfiable range is `416` with `Content-Range: bytes */<len>`.
- Every response gets `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, and a
  `Content-Security-Policy` of at least `frame-ancestors 'none'`.
- SVG is served with `Content-Security-Policy: sandbox` and
  `Content-Disposition: attachment`; other non-inline types are attachments.

## Endpoints

### `GET /healthz`

No auth. `200` with `{"ok":true,"free_bytes":N}` when the `galleries` and
`photos` tables are readable, `photos/` is readable, and free space is at
least `GALLY_MIN_FREE_BYTES`. Otherwise `503` with
`{"ok":false,"free_bytes":N}`. A background sweep reaps stale upload-part
temps every ten minutes; health checks also do one pass at most once a
minute. Uploads no longer scan the whole `photos/` directory.

### `GET /metrics`

Prometheus text. Only a direct loopback socket with no forwarding header and
whose peer is not listed in `GALLY_TRUST_PROXY` may scrape; otherwise `404`.
In Compose, scrape inside the app container's network namespace. Explicitly
block `/metrics` and the admin paths at the public reverse proxy.

Metrics: `gally_uptime_seconds`, `gally_free_bytes`, `gally_galleries`,
`gally_photos`, `gally_bytes`, `gally_requests_total`,
`gally_responses_5xx_total`, `gally_uploads_total`,
`gally_upload_bytes_total`.

### `POST /api/galleries/resolve`

Mint a gallery or verify that a key owns a slug. A bodyless request is
allowed. An optional JSON body, up to 8 KiB, requires
`Content-Type: application/json` when sent (`415` otherwise); the body `key`
remains supported:

```json
{ "key": "Sunset-Beach-42", "slug": "velvet-lagoon-quiet-river-1a2b" }
```

An empty or whitespace-only body is the bodyless form; any other non-empty
body must be a JSON object, and malformed JSON or a non-object body is
`400 bad request` and never mints a gallery.

The header key wins if both are present. With no `slug` key (or a bodyless
request), every call mints a fresh gallery (same key, new gallery);
`X-Invite-Code` is checked when configured.
There is deliberately no lookup by key alone: one key can own several
galleries, and only a slug plus key identifies one.
With a slug, it answers `200 {"slug":...}` only when the key owns that gallery;
otherwise `403 forbidden` (or `429` once the failure bucket is full). A
wrong invite code also counts toward the 10/min/IP failure bucket: the first
attempts are `403`, and further attempts are `429` once the bucket is full. A
correct code still works. A malformed slug is `400 bad slug`; a present `slug`
must be a non-empty valid slug string, so an empty or whitespace value is
`400` even with no key. Missing key is
`401 gallery key required`.
Body over 8 KiB is `413`; a stalled body is `408`.

### `GET /api/galleries/{slug}/photos`

Query: `limit` (1–1000, default 500), `before` (the `next` cursor from a
previous page). Headers: `X-Gallery-Key` and/or `X-Gallery-Pass`.

```json
{
  "slug": "velvet-lagoon-quiet-river-1a2b",
  "public": false,
  "locked": true,
  "photos": [{ "name": "velvet-lagoon-quiet-river-1a2b_0123..._photo.jpg" }],
  "next": "1794932697584:velvet-lagoon-quiet-river-1a2b_0123..._photo.jpg"
}
```

`next` is `null` when the page is not full; otherwise feed it back as
`before`. The array carries stored names only; fetch previews from
`/photos/thumb/<name>.jpg` and originals from `/photos/<name>`.

Status: `404 unknown gallery` for an unknown or private gallery when the
request is not the owner; `401 {"error":"gallery locked","locked":true}` for a
public locked gallery without a valid password; `400 bad cursor`; `429` for
the read limit or repeated wrong keys. A listing with the owner key sets
`galowner_<slug>`; a successful viewer password sets `galpass_<slug>`.

### `POST /api/galleries/{slug}/visibility`

Owner key only. Body `{"public": true}` or `{"public": false}`, up to 8 KiB,
with `Content-Type: application/json` (`415` otherwise).

```json
{ "slug": "velvet-lagoon-quiet-river-1a2b", "public": true }
```

`400` for malformed JSON, `415` for a missing or wrong content type, `401`
without a key, `403` when the key does not own the gallery, `404` for an
unknown slug, `429` at the rate limit.

### `POST /api/galleries/{slug}/lock`

Owner key only. Body `{"password": "..."}` sets an Argon2id viewer password;
an empty or missing password clears it. The body must be
`Content-Type: application/json` (`415` otherwise). Malformed JSON is `400`
and never silently clears an existing lock.

```json
{ "slug": "velvet-lagoon-quiet-river-1a2b", "locked": true }
```

Changing the password bumps the token version, so all existing viewer cookies
stop working. Viewer requests overlapping a change may be denied; retry with
the current password. `401`/`403`/`404`/`429` as above.

### `PUT /api/photos/{name}`

Headers: `X-Gallery-Key`; `X-Gallery-Slug` (optional for full-body, required
for chunked); `X-Invite-Code` when minting with an invite configured.
A present `X-Gallery-Slug` must be a valid slug; an invalid or non-UTF-8 value
is `400 bad slug` and never mints. `Content-Type` is not used to decide the
stored type; the filename extension does. Path separators in `name` are
stripped by the sanitizer.

#### Full-body upload

No `Content-Range` and no `X-Upload-Id`: send the whole file as the request
body. The response is `201`:

```json
{ "name": "velvet-lagoon-quiet-river-1a2b_<32 hex>_photo.jpg",
  "slug": "velvet-lagoon-quiet-river-1a2b" }
```

With no slug, the key mints a fresh gallery (invite applies). With a slug, the
key must own it. Empty body is `400 empty body`; oversize/quota is `413`;
free-space floor is `507`; no upload slot is `503 busy`; idle timeout is `408`.

#### Resumable upload

Send **both** `X-Upload-Id` (32 hex, case-insensitive) and `Content-Range`:

```http
Content-Range: bytes 0-8388607/12582912
```

`start` and `end` are inclusive; `total` is the final file size; `start <= end
< total`; `total` cannot be 0. `X-Gallery-Slug` is required. Chunks must be
contiguous: the existing temp length must equal `start`. Keep the filename
and total unchanged, and use a different ID for each file in a gallery.

| Response | Meaning |
|---|---|
| `202 {"received":N}` | Chunk written and flushed; continue from `N` |
| `201 {name,slug}` | Final chunk stored, or the matching upload is already complete |
| `409 {"error":"offset mismatch","received":N}` | Server has N bytes; jump to N |
| `409 {"error":"upload in progress"}` | Another request owns this gallery's upload ID; back off and retry the same offset |
| `409 {"error":"upload id already used"}` | A saved file or row for this ID does not match this request; use a different ID for a different file |
| `410 {"error":"upload expired"}` | Temp is gone (restart, startup sweep, or 1 h TTL); restart at 0 with the same id |
| `400` | Bad headers, a chunk overrun, an empty body, or `temp > total` |
| `408` | Idle timeout, short body, or a chunk shorter than its declared range |
| `413` / `507` / `503` | File/gallery limits, free-space floor, or no slot |
| `429` | The first chunk (`start=0`) consumes the upload bucket, and every chunk consumes the chunk bucket (`600/min/IP`), so later chunks can also be throttled; honor `Retry-After` |

On an interrupted or rejected chunk the server rolls back to the last
flushed, accepted prefix. A lost final response can be retried without
writing the same bytes again. The final chunk is made durable (file sync,
rename, directory sync) before the quota-checked DB commit and `201`.
A DB error after rename returns `500` and keeps the unindexed original;
a matching retry or the next startup recount can restore the row.
Active uploads reserve gallery bytes and space before writing. Full-body
uploads without `Content-Length` reserve incrementally. Idle `.part-*`
prefixes still count toward gallery quota and use disk space until reclaimed
after one hour. Disk accounting cannot reserve space against other processes.

Limits: `GALLY_MAX_BYTES` (10 GiB), `GALLY_GALLERY_MAX_BYTES` (5 GiB),
`GALLY_GALLERY_MAX_PHOTOS` (5000), `GALLY_MIN_FREE_BYTES` (2 GiB),
`GALLY_UPLOAD_SLOTS` (32 global), `GALLY_UPLOAD_SLOTS_PER_IP` (4). Disable the
gallery/free-space limits with `0`.

EXIF capture time is extracted only from files of 16 MiB or less (also for
startup backfill). Larger files are stored unchanged and keep the normal
upload-time or existing-date fallback.

### `GET /photos/{name}` and `GET /photos/thumb/{name}.jpg`

Serve the original or its preview. Auth: `X-Gallery-Key`, the owner or viewer
media cookie (`galowner_*`/`galpass_*`), or `X-Gallery-Pass`. Media tags rely
on the cookie. A private gallery without the owner is
`404`; a public locked gallery without a password is
`401 {"error":"gallery locked","locked":true}`. Both originals and previews
require the original's DB row. A missing preview is `404`; the client falls
back to the original.

| Extension | Served as |
|---|---|
| `.jpg/.jpeg`, `.png`, `.gif`, `.webp`, `.avif`, `.bmp`, `.ico`, `.svg`, `.heic/.heif` | Image type |
| `.mp4`, `.webm`, `.mov`, `.ogv` | Video type |
| `.mp3`, `.wav`, `.ogg/.oga/.opus`, `.flac`, `.m4a` | Audio type; OGG/Opus is sniffed for Theora/Vorbis/Opus |
| `.pdf`, `.txt`, `.json`, `.md` | Document/text types |
| anything else | `application/octet-stream`, attachment |

Previews exist only for JPG/JPEG, PNG, GIF, WebP, BMP, and ICO uploads. They
are JPEG, 400 px on the long edge, quality 80. Photos uploaded before the
preview feature have no preview.

### `DELETE /api/photos/{name}`

Owner key or admin cookie. `name` must be a stored name (no slash, backslash,
or leading dot) and must resolve inside `photos/`. Response:

```json
{ "deleted": "velvet-lagoon-quiet-river-1a2b_0123..._photo.jpg",
  "gallery_gone": false }
```

`404` for unknown/not-yours; `500` if the DB update fails after the file
removal. A retry after the file is gone clears the stale row and returns
`200`; a later recount also drops it. The gallery row is kept.

### `DELETE /api/galleries/{slug}`

Owner key or admin cookie. Removes the DB row and the gallery's originals,
previews, and upload temps. Response `200 {"deleted":"...","files":N}`. A
failed or incomplete sweep is `500` with `{"deleted":"...","files":N,
"error":"partial delete"}`; the row is already gone. The key itself stays
valid and can mint a new gallery.

### Admin

All admin routes require the `admin` cookie except the unlock route. Unlock
takes JSON and requires `Content-Type: application/json` (`415` otherwise).
If `ADMIN_PASS` is unset, unlock answers `404` and the other routes answer
`403`.

| Route | Body | Success |
|---|---|---|
| `POST /api/admin/unlock` | `{"password":"..."}` | `200 {"ok":true}` + `admin` cookie; `403` wrong, `429` locked out, `404` admin disabled |
| `GET /api/admin/galleries` | optional `limit` (default 200, 1–1000) and `before` | `200 {"galleries":[{slug,created,photos,bytes,public}],"next":...}`; `created` is Unix seconds |
| `POST /api/admin/galleries/{slug}/remove` | — | `200 {"deleted":slug,"files":N}`; `404`; `500` partial |
| `POST /api/admin/sweep` | — | `200 {"deleted":N,"failed":N,"galleries":N}`; removes orphaned files, expired temps, and empty galleries older than one hour |
| `POST /api/admin/logout` | — | `200 {"ok":true}`; clears the cookie. Without a live admin session: `403 {"error":"admin session inactive"}`; a generic `403` is not proof of logout |

The admin cannot recover keys or passwords, and cannot read a private
gallery's photos. Deleting a gallery does not revoke its key. The gallery
list uses `created:slug` as its `before` cursor and returns `next` until the
last page; the admin page uses 200-row pages.

### Static and SPA routes

| Route | Behavior |
|---|---|
| `GET /` | `index.html`, `no-cache` |
| `GET /{slug}` | Valid slug → `index.html`; invalid slug → `302 /` |
| `GET /gally/admin/` | Admin page |
| `GET /gally/admin` | `308 /gally/admin/` |
| `GET /app.js`, `/styles.css`, `/index.html`, `/fonts/*`, `/vendor-heic2any.min.js` | Static asset with ETag |
| Anything else | `404 {"error":"not found"}` |

A valid-but-unknown slug gets the SPA (which then loads a listing and
redirects on `404`), so the page route does not reveal whether a private
gallery exists.

## Chunked upload: raw example

```
PUT /api/photos/photo.jpg HTTP/1.1
Host: 127.0.0.1:8000
X-Gallery-Key: Sunset-Beach-42
X-Gallery-Slug: velvet-lagoon-quiet-river-1a2b
X-Upload-Id: 0123456789abcdef0123456789abcdef
Content-Range: bytes 0-8388607/12582912
Content-Length: 8388608

<8388608 bytes>
```

`202 {"received":8388608}`. Then:

```
PUT /api/photos/photo.jpg HTTP/1.1
Host: 127.0.0.1:8000
X-Gallery-Key: Sunset-Beach-42
X-Gallery-Slug: velvet-lagoon-quiet-river-1a2b
X-Upload-Id: 0123456789abcdef0123456789abcdef
Content-Range: bytes 8388608-12582911/12582912
Content-Length: 4194304

<4194304 bytes>
```

`201 {"name":"velvet-lagoon-quiet-river-1a2b_0123456789abcdef0123456789abcdef_photo.jpg","slug":"velvet-lagoon-quiet-river-1a2b"}`.

## `curl` examples

Mint a gallery and upload one file:

```sh
KEY='Sunset-Beach-42'
SLUG=$(curl -fsS -X POST http://127.0.0.1:8000/api/galleries/resolve \
  -H "X-Gallery-Key: $KEY" -H 'Content-Type: application/json' -d '{}' \
  | jq -r .slug)

curl -fsS -X PUT "http://127.0.0.1:8000/api/photos/photo.jpg" \
  -H "X-Gallery-Key: $KEY" -H "X-Gallery-Slug: $SLUG" \
  --data-binary @photo.jpg

curl -fsS "http://127.0.0.1:8000/api/galleries/$SLUG/photos" \
  -H "X-Gallery-Key: $KEY"
```

Resumable upload, first 8 MiB chunk of a larger file:

```sh
ID=0123456789abcdef0123456789abcdef
TOTAL=$(stat -c%s photo.jpg)
head -c 8388608 photo.jpg > chunk0

curl -fsS -X PUT "http://127.0.0.1:8000/api/photos/photo.jpg" \
  -H "X-Gallery-Key: $KEY" -H "X-Gallery-Slug: $SLUG" \
  -H "X-Upload-Id: $ID" \
  -H "Content-Range: bytes 0-8388607/$TOTAL" \
  --data-binary @chunk0
```

A `202` carries the committed offset; send the next chunk from it. On
`409 offset mismatch` jump to `received`; on `410 upload expired` restart at
zero with the same id.

Protect a gallery, then unlock with the viewer password and reuse the cookie:

```sh
curl -fsS -X POST "http://127.0.0.1:8000/api/galleries/$SLUG/lock" \
  -H "X-Gallery-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"password":"viewer-pass"}'

NAME=$(curl -fsS -c jar -X GET \
  "http://127.0.0.1:8000/api/galleries/$SLUG/photos" \
  -H 'X-Gallery-Pass: viewer-pass' | jq -r '.photos[0].name')

curl -fsS -b jar "http://127.0.0.1:8000/photos/$NAME"
```

Admin login and listing:

```sh
curl -fsS -c admin.jar -X POST http://127.0.0.1:8000/api/admin/unlock \
  -H 'Content-Type: application/json' -d '{"password":"..."}'

curl -fsS -b admin.jar http://127.0.0.1:8000/api/admin/galleries
```

## Failure behavior

- Startup takes the data-dir lock, sweeps `.part-*` and `.tmp-*`, opens and
  migrates SQLite, recounts counters from `photos/`, and backfills missing EXIF
  capture times. An interrupted upload does not survive a restart; restart
  that file from zero. If the database has photo rows but `photos/` contains
  none of them, startup fails instead of rebuilding an empty index; restore the
  files, or move both `galleries.db` and `photos/` aside to start a fresh
  library.
- A final upload is synced and renamed before the DB row is added. A DB error
  keeps the file, returns `500`, and the next recount adopts it.
- A database read error is a `500`, never a missing gallery, a missing
  password, or an orphaned file: the admin sweep aborts without deleting.
- SQLite runs with WAL and `synchronous=FULL`: an acknowledged upload row,
  visibility change, or viewer-password change survives a power cut.
- A photo delete removes and syncs the file before updating counters; a DB
  error returns `500` and a later recount removes the stale row.
- A gallery delete refuses to touch the row if `photos/` cannot be read; a
  partial sweep after the row is gone returns `500`.
- The server is single-node. The data-dir lock prevents a second writer; the
  rate limits and admin tokens are in process memory; the media-cookie secret
  must be stable across restarts (`GALLY_MEDIA_SECRET` or the generated file).
